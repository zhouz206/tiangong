## 1. 产品概述

### 1.1 项目愿景
打造一个轻量、高效、可扩展的 AI 协作平台，让个人开发者和小团队能够像拥有专业团队一样完成复杂工作。

### 1.2 目标用户
- **个人开发者**：需要自动化工作流的独立开发者（1-2人）
- **小团队**：3-10人的小型团队，希望用 AI 辅助日常协作
- **自由职业者**：需要多角色协作完成项目的个体工作者

> **明确排除**：大型企业用户（暂不考虑复杂的合规、审计、大规模部署需求）

### 1.3 核心价值
- **效率提升**：自动化复杂工作流，减少重复性人工干预
- **知识沉淀**：自动归档项目知识，形成个人/团队记忆
- **成本优化**：智能路由选择最合适的模型，控制使用成本
- **安全保障**：基础的安全机制，保护个人数据和 API 密钥
- **开放扩展**：支持 Skill 和 MCP 集成，按需扩展能力

### 1.4 核心特性概览

| 特性类别 | 核心能力 | 用户价值 |
|----------|----------|----------|
| **多 Agent 协作** | 角色分工、上下游协作、局部讨论 | 像专业团队一样高效协作 |
| **混合模型支持** | 云端+本地模型、智能路由、自动降级 | 成本最优，可靠性最高 |
| **能力扩展** | Skill 动态加载、MCP 工具调用、安全沙箱 | 按需扩展，避免过度工程 |
| **知识管理** | 自动归档、语义搜索、知识关联 | 项目知识自动沉淀复用 |
| **执行追溯** | 完整操作日志、成本分析、简单审计 | 透明可控，便于复盘 |
| **安全协作** | 基础权限、敏感信息过滤、讨论隐私 | 保护个人数据安全 |

## 2. 用户场景

### 2.1 典型工作流

#### 场景：个人开发者构建 SaaS 应用
```
用户创建"SaaS 应用开发"项目
├── 启动阶段
│   ├── 项目经理Agent：明确项目目标和范围
│   └── 研究员Agent：调研竞品和技术方案
├── 规划阶段  
│   ├── 项目经理Agent：拆解任务，分配角色
│   └── 架构师Agent：设计系统架构
├── 执行阶段
│   ├── 前端工程师Agent：开发UI界面
│   ├── 后端工程师Agent：实现API接口
│   └── 数据库工程师Agent：设计数据库
├── 审查阶段
│   ├── 测试工程师Agent：编写测试用例
│   └── 安全审计Agent：安全漏洞扫描
├── 完成阶段
│   ├── 交付专员Agent：生成部署文档
│   └── 文案Agent：编写用户手册
└── 归档阶段
    └── 知识管理员Agent：整理项目知识库
```

#### 场景：小团队内容创作
```
用户创建"技术博客系列"项目
├── 启动阶段
│   ├── 编辑Agent：确定主题和大纲
│   └── 研究员Agent：收集相关资料
├── 执行阶段
│   ├── 作者Agent：撰写文章初稿
│   ├── 设计师Agent：制作配图和排版
│   └── 技术专家Agent：审核技术准确性
├── 审查阶段
│   ├── 编辑Agent：最终校对和润色
│   └── SEO专家Agent：优化搜索引擎友好度
└── 发布阶段
    └── 发布专员Agent：自动发布到各平台
```

#### 关键交互点：
- **Agent 协作**：任务完成后自动触发下游 Agent（简化版，避免复杂依赖）
- **局部讨论**：相关 Agent 就具体问题进行私有讨论
- **Skill 调用**：按需调用代码分析、图像处理等专业 Skill
- **MCP 集成**：通过 MCP 调用文件系统、数据库等工具
- **知识沉淀**：项目完成后自动归档所有产出物

### 2.2 用户角色与权限

| 角色 | 权限范围 | 典型操作 |
|------|----------|----------|
| **工作空间所有者** | 完全控制 | 创建/删除工作空间，管理成员，导出数据 |
| **协作者** | 任务创建/修改 | 参与任务执行，参与讨论，提交产出物 |
| **观察者** | 只读权限 | 查看项目进度，阅读文档，查看追溯日志 |

> **简化说明**：移除"项目管理员"角色，所有者直接管理项目，降低权限复杂度

## 3. 详细功能规格

### 3.1 工作空间管理

#### 3.1.1 单工作空间优先
- **个人模式**：默认单工作空间，简化使用体验
- **多工作空间**：支持创建多个工作空间（可选功能）
- **成员管理**：邀请协作者，分配基础权限
- **资源监控**：显示模型调用统计和成本估算

#### 3.1.2 项目模板（精简版）
- **预置模板**：
  - 软件开发模板（程序员、测试员、架构师）
  - 内容创作模板（文案、编辑、设计师）
  - 数据分析模板（数据分析师、可视化专家）
- **自定义模板**：保存常用项目配置为模板
- **模板导入**：支持从社区导入优质模板

#### 3.1.3 项目克隆
- **快速启动**：基于现有项目快速创建新项目
- **配置继承**：继承原项目的 Agent 配置和模型设置
- **数据隔离**：新项目数据完全独立

### 3.2 项目生命周期管理

#### 3.2.1 四阶段简化工作流
```
规划 → 执行 → 审查 → 完成
```

**各阶段详细说明：**

| 阶段 | 目标 | 典型 Agent | 产出物 |
|------|------|-----------|--------|
| **规划** | 明确目标、拆解任务、分配角色 | 项目经理、架构师 | 任务列表、架构设计 |
| **执行** | 完成任务、产出结果 | 研究员、程序员、设计师 | 代码、设计稿、报告 |
| **审查** | 质量检查、风险评估 | 审核员、测试员 | 测试报告、审核意见 |
| **完成** | 交付成果、知识归档 | 交付专员、知识管理员 | 交付包、知识库 |

> **简化说明**：移除"启动"和"归档"阶段，合并到规划和完成阶段

#### 3.2.2 项目状态管理（简化版）
- **进行中**：正常执行任务
- **暂停**：临时停止，保留上下文
- **完成**：所有任务完成，进入知识归档
- **取消**：主动终止项目，保留历史记录

#### 3.2.3 状态转换规则（简化）
- 暂停 ↔ 进行中：双向切换
- 进行中 → 完成：所有任务完成
- 任何状态 → 取消：主动终止

#### 3.3.2 Agent 能力扩展（实用导向）

##### Skill 集成（简化版）
- **动态加载**：Agent 可在运行时加载/卸载 Skill
- **内置 Skill**：提供常用 Skill（代码分析、安全扫描、格式化等）
- **权限控制**：Skill 执行受基础权限限制
- **社区 Skill**：支持从社区安装第三方 Skill

**Skill 开发规范（简化）：**
```python
class BaseSkill:
    def __init__(self, config):
        self.config = config
    
    def execute(self, context, **kwargs):
        # 执行技能逻辑
        pass
```

##### MCP (Model Context Protocol) 集成（核心工具）
- **标准化工具调用**：通过 MCP 协议调用外部服务
- **内置 MCP 服务**：
  - 文件系统：读写本地文件
  - 数据库：基本 SQL 查询
  - HTTP 客户端：API 调用
- **安全沙箱**：MCP 调用在受限环境中执行

**MCP 服务配置（简化）：**
```yaml
mcp_services:
  - name: "file_system"
    endpoint: "http://localhost:8080/mcp/filesystem"
    capabilities: ["read", "write"]
    
  - name: "database"  
    endpoint: "http://localhost:8080/mcp/database"
    capabilities: ["query"]
```

#### 3.3.3 Agent 配置（实用配置）

**完整配置示例（简化版）：**
```yaml
agent:
  # 基础信息
  name: "Python 工程师"
  role: "coder"
  description: "专注于 Python 代码开发"
  
  # 系统提示
  system_prompt: |
    你是一位 Python 工程师，擅长：
    - 编写清晰、可维护的代码
    - 遵循最佳实践
    - 编写单元测试
  
  # 模型配置
  model: "gpt-4"
  temperature: 0.7
  max_tokens: 2048
  
  # 协作关系
  upstream: ["需求分析师"]
  downstream: ["测试工程师"]
  
  # 能力声明
  capabilities:
    - languages: [python]
    - frameworks: [fastapi, flask]
    - tools: [git, docker]
  
  # 技能配置
  skills:
    - name: "code_analysis"
      enabled: true
      
    - name: "security_scan" 
      enabled: true
  
  # MCP 服务
  mcp_services:
    - name: "file_system"
    - name: "database"
```

#### 3.3.4 Agent 协作模式（可靠协作）

##### 任务传递机制（简化可靠版）
- **手动触发**：用户确认后触发下游 Agent（避免自动触发的不确定性）
- **状态同步**：任务状态实时同步
- **简单依赖**：支持单一上游依赖

##### 局部讨论机制
- **私有讨论**：仅相关 Agent 可见的讨论区
- **上下文共享**：自动共享相关上下文
- **用户可见**：所有讨论对项目所有者可见

##### 能力协同机制
- **跨 Agent 调用**：Agent 可调用其他 Agent 的基础能力
- **权限验证**：跨 Agent 调用需验证权限

### 3.4 模型管理

#### 3.4.1 支持的模型提供商（精选）

| 类型 | 提供商 | 推荐模型 | 特点 |
|------|--------|---------|------|
| **云端** | OpenAI | GPT-4o, GPT-3.5 | 通用能力强，稳定可靠 |
| **云端** | Anthropic | Claude-3.5-Sonnet | 长上下文，推理强 |
| **云端** | 阿里云 | 通义千问 (Qwen-Max) | 中文优化，性价比高 |
| **本地** | Ollama | Llama3, Qwen | 隐私保护，离线可用 |

> **优化说明**：移除智谱 AI 和 vLLM，聚焦主流和易用的选项

#### 3.4.2 模型配置管理（简化）

**模型配置示例：**
```yaml
models:
  - id: gpt4o
    name: "GPT-4o"
    provider: "openai"
    api_key: "${OPENAI_API_KEY}"
    model_name: "gpt-4o"
    context_limit: 128000
    priority: 1
    cost_per_token: 0.00001
    
  - id: qwen-local
    name: "Qwen 本地"
    provider: "ollama"
    endpoint: "http://localhost:11434"
    model_name: "qwen2.5:7b"
    context_limit: 32000
    priority: 2
    cost_per_token: 0.0
    offline: true
```

#### 3.4.3 智能路由策略（实用版）

- **成本优先**：默认使用性价比最高的模型
- **能力匹配**：复杂任务自动选择更强模型
- **本地优先**：支持离线场景，优先使用本地模型
- **简单降级**：主模型失败时切换到备用模型

**路由决策流程（简化）：**
```
接收请求 → 分析任务类型 → 选择合适模型 → 执行调用 → 失败则降级
```

- **简单审计**：关键操作记录

### 3.7 安全与权限

#### 3.7.1 三级权限模型（简化）

| 权限级别 | 说明 | 可执行操作 |
|----------|------|-----------|
| **工作空间所有者** | 完全控制 | 所有操作 + 成员管理 + 删除 |
| **协作者** | 任务创建/修改 | 任务执行 + 讨论参与 + 产出提交 |
| **观察者** | 只读权限 | 查看进度 + 阅读文档 + 查看日志 |

#### 3.7.2 安全特性（基础安全）

- **敏感信息过滤**：自动检测并屏蔽 API 密钥、密码等
- **模型密钥加密**：API 密钥加密存储
- **讨论隐私**：上下游讨论仅对相关成员可见
- **基础审计**：关键操作记录
